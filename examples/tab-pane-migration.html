    Four-stage workflow

    1. Analyze the legacy contract

      Scan callers, methods, events, DOM work, styles, dependencies, and unknown forms.

      npm run migrate -- analyze tab-pane

      Artifacts

      • worksheet.generated.json
      • Decision stubs in migration.json only when no decisions exist

    2. Preview the adapter Dry run by default

      The first command prints the complete plan. Run the second command only after approval. It applies every edit or restores the original files.

      The host or browser proof runner sets the configured implementation value before bootstrap. Both proof surfaces load /. Bootstrap creates the table manager from the injected value, not the URL.

      npm run migrate -- adapter tab-pane
npm run migrate -- adapter tab-pane --write

    3. Capture the legacy fallback baseline

      Inject legacy-TabPane before bootstrap, run the focused legacy test through the shared mount, then capture observations, screenshots, and one WebM per scenario.

      npm run migrate -- baseline tab-pane \
  --base-url http://127.0.0.1:5173

      Artifacts

      • baseline/manifest.json
      • baseline/recordings/<scenario>.webm
      • baseline/<scenario>/<name>.png

    4. Verify React parity

      Inject react-TabPane before bootstrap, then run both focused tests, project checks, browser scenarios, exact image comparisons, and approved behavior checks.

      npm run migrate -- verify tab-pane \
  --base-url http://127.0.0.1:5173

      Artifacts

      • final/manifest.json and final/parity.json
      • final/recordings/<scenario>.webm
      • final/<scenario>/<name>.png
      • final/diffs/<scenario>/<assertion>.png
      • final.failed/ when verification does not reach parity
